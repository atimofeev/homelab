# Paperless-ngx

Paperless-ngx runs from Kubernetes manifests in this directory. PostgreSQL is
managed by CloudNativePG. Valkey is managed by a local StatefulSet and runs
without authentication; NetworkPolicy restricts it to the Paperless pod.
The MCP server is a separate internal Deployment.

All Paperless credentials are generated inside the cluster. No Bitwarden item
is required for Paperless.

## Deploy

1. Commit and push this directory. ArgoCD creates the namespace, generated
   Django and admin Secrets, CNPG cluster, generated database Secret, Valkey,
   Paperless, API-token bootstrap Job, and MCP resources.
2. Wait for Paperless and the bootstrap Job:

   ```bash
   kubectl rollout status deployment/paperless-ngx -n paperless-ngx --timeout=15m
   kubectl wait --for=condition=complete job/paperless-api-token-bootstrap \
     -n paperless-ngx --timeout=20m
   ```
3. Retrieve generated admin password when logging in:

   ```bash
   kubectl get secret paperless-admin-secret -n paperless-ngx \
     -o jsonpath='{.data.password}' | base64 -d
   echo
   ```
4. Open `https://paperless.prosto.dev` and log in as `admin`.

Do not commit credentials or generated Kubernetes Secrets to Git.

## Generated credentials

External Secrets Operator generates these immutable Secrets with
`refreshPolicy: CreatedOnce` and `creationPolicy: Orphan`:

- `paperless-django-secret/password` feeds `PAPERLESS_SECRET_KEY`.
- `paperless-admin-secret/password` feeds `PAPERLESS_ADMIN_PASSWORD`.

Paperless only uses `PAPERLESS_ADMIN_PASSWORD` when creating the initial
`admin` superuser. Changing the generated Secret later does not change an
existing user's database password. Change that password through Paperless if
needed.

The `paperless-api-token-bootstrap` Job waits for Paperless, authenticates as
`admin`, calls Paperless `/api/profile/generate_auth_token/`, and writes the
result to `paperless-api-secret/api-key`. MCP reads that Secret. The Job has
namespace-scoped permission to manage only Kubernetes Secrets in its namespace
and does not print token values.

The Job is idempotent: if `paperless-api-secret` already contains `api-key`, it
exits without creating another token. ArgoCD runs it as a Sync hook after the
Paperless Deployment wave.

If bootstrap fails, inspect the Job and retry an ArgoCD sync:

```bash
kubectl logs job/paperless-api-token-bootstrap -n paperless-ngx
argocd app sync paperless-ngx
```

To intentionally rotate the MCP token, delete `paperless-api-secret` and sync
the ArgoCD Application again. Paperless generates a new token and invalidates
the previous one. Do not rotate the Django Secret during ordinary upgrades;
changing it invalidates sessions and signed data.

## Generated database credentials

CloudNativePG creates `cnpg-paperless-app` during first bootstrap. The
Paperless Deployment reads only its `password` key. The Secret also contains
connection metadata and URI variants generated by CNPG; those values remain
owned by CNPG and are not copied into another credential store.

`bootstrap.initdb` runs only when the PostgreSQL cluster is initialized. Do not
remove or change bootstrap credentials on an already initialized cluster
without planning a password migration.

## MCP access

MCP uses Streamable HTTP on the internal Service `paperless-mcp:3000`. It has no
HTTP authentication and no public HTTPRoute.

Use `kubectl port-forward` for local testing:

```bash
kubectl port-forward -n paperless-ngx svc/paperless-mcp 3000:3000
```

Then configure an MCP client with endpoint `http://127.0.0.1:3000/mcp`.
For an in-cluster agent, add a narrower ingress rule to
`paperless-network-policy.yaml`. Put an authenticated proxy in front of MCP
before allowing access outside the cluster.

## Validation

```bash
kubectl get password,externalsecret -n paperless-ngx
kubectl get secret paperless-admin-secret paperless-django-secret \
  paperless-api-secret -n paperless-ngx
kubectl get cluster,pods,pvc -n paperless-ngx
kubectl wait --for=condition=Ready cluster/cnpg-paperless \
  -n paperless-ngx --timeout=15m
kubectl rollout status statefulset/paperless-ngx-valkey \
  -n paperless-ngx --timeout=10m
kubectl rollout status deployment/paperless-ngx \
  -n paperless-ngx --timeout=15m
kubectl rollout status deployment/paperless-mcp \
  -n paperless-ngx --timeout=10m
```

Paperless uses `ReadWriteOnce` claims and a `Recreate` strategy. Updates cause
a short outage. Back up the archive before changing Paperless major versions.
